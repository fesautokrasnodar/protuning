## 2. Функциональная карта основного прототипа

### 2.1 Калькулятор / КП
- выбор автомобиля (dropdown из `models`);
- клиент / компания (текст), контакт (текст);
- список услуг с чекбоксами и ценой **только для услуг с ценой ≥ 0** для выбранной модели;
- «Выбрать все» и «Очистить»;
- смена автомобиля **сбрасывает** выбор услуг;
- итог = сумма цен выбранных услуг, формат `Intl.NumberFormat('ru-RU')` + ` ₽`;
- живое КП A4 (794×1123 px):
  - шапка: логотип + «ПЕРСОНАЛЬНОЕ ПРЕДЛОЖЕНИЕ» + дата (`ru-RU`);
  - hero: название автомобиля + фото;
  - meta-блок: Автомобиль / Клиент / Контакт;
  - нумерованный список услуг «Комплектация работ»;
  - чёрная плашка «ИТОГО» с красными диагональными акцентами;
  - 3 статичных блока преимуществ;
  - сноска-дисклеймер.
- печать: `@page A4; margin:0`, hide UI, `.proposal` = 210mm×297mm. Подсказка «включите фоновую графику».

### 2.2 Прайс-матрица
- строки — услуги (инлайн-переименование), столбцы — автомобили (инлайн-бренд/модель);
- ячейка — цена (`<input type=number min=0 step=100>`), пустая = «услуга не предлагается / цена не задана»;
- фото авто: upload → сжатие canvas (max 1200×760, JPEG q≈0.82) → Base64 dataURL в localStorage;
- замена фото, удаление фото;
- удаление автомобиля (каскадно удаляет его цены), удаление услуги (удаляет строку цен);
- добавление автомобиля / услуги с пустыми ценами;
- автосохранение: debounce 250 мс → `localStorage[proTuningUnifiedV1]`;
- индикатор «Сохраняю… / Данные сохранены / ошибка (переполнение хранилища)» + `alert()`;
- export/import JSON (валидация — только наличие ключей `services`, `models`, `prices`).

## 3. Структура данных прототипа

```js
{
  services: [{ id, name }],                 // 6 услуг из коробки
  models:   [{ id, brand, model, photo }],  // photo = dataURL или ""
  prices:   { serviceId: { modelId: number|"" } }
}
```

Исторические форматы:
- `proTuningPrices` (плоский): `[{ id, brand, model, service, price, icon }]` — ранние версии.

## 4. Бизнес-правила (извлечено из кода)

1. Пустая цена (`""`, `null`, `undefined`) ⇒ услуга недоступна для этой модели; в расчёте и списке не участвует.
2. Смена автомобиля в калькуляторе сбрасывает выбор услуг.
3. При смене модели невалидные (ставшие недоступными) выбранные услуги молча вычищаются.
4. Итог = Σ цен выбранных услуг (целые рубли, без скидки в прототипе).
5. Удаление авто/услуги каскадно чистит цены.
6. Изменения прайса немедленно отражаются в калькуляторе и КП (единый `data`).
7. Дата КП: `new Date().toLocaleDateString('ru-RU')`.
8. Новая пустая услуга/авто получает `uid`; цены инициализируются пустыми.

## 5. UI и стиль

- Палитра: `red #d71920`, `black #0d0d0f`, `ink #17171a`, `muted #74747b`, `line #dedee2`, `soft #f4f4f6`, `white #fff`.
- Премиальный automotive-стиль: чёрная шапка с красной полосой, строгая типографика, красные акценты-«скосы», крупное фото автомобиля.
- Монолитные вкладки (калькулятор / матрица), topbar с save-flag, панели с тенью и радиусом 16px.
- Responsive: при ≤1000px колонки стекаются, матрица горизонтально скроллится.

## 6. Ограничения и баги прототипа

1. **Фото как Base64 в localStorage** — лимит ~5 МБ, `alert()` при переполнении; фото не шарится между устройствами.
2. **Нет сохранения КП** — список, статусы, номера отсутствуют.
3. **Нет авторизации, ролей, RLS.**
4. **Import JSON без валидации схемы** (проверка только 3 ключей).
5. **Цены**: смесь `""` и `number`; в бизнес-логике не строгий тип.
6. **`alert()`/`confirm()`** как основной UI.
7. **Глобальный `selected`** (Set) — состояние сессии, но живёт в модуле и переживает переключение вкладок; теряется при принудительной перерисовке.
8. Нет скидки, количества услуг, статусов, истории цен.
9. `hero-photo img` без alt и без обработки ошибки загрузки сломанного dataURL.
10. Печать требует «фоновой графики» — красные элементы могут пропадать.

## 7. Что сохраняется / мигрируется / меняется / добавляется

**Сохраняется (переносится «как есть»):**
- бизнес-правила 1–8 раздела 4;
- визуальный язык, палитра, layout КП и матрицы;
- форматирование денег (`ru-RU` + ` ₽`);
- сжатие фото до 1200×760 JPEG;
- автосохранение-концепция (теперь через server-state слой);
- экспорт/импорт резервной копии.

**Мигрируется:**
- `models[]` → таблица `cars` (+ `photo` → `photo_url`);
- `services[]` → таблица `services`;
- `prices{sid:{mid}}` → таблица `prices(car_id, service_id, price)` с уникальным constraint;
- `""` цена → `null`.

**Меняется:**
- localStorage → хранилище через интерфейс (mock → Supabase);
- монолитные вкладки → маршрутизация;
- синхронная перерисовка DOM → компонентная модель + TanStack Query;
- `alert/confirm` → диалоги/toasts.

**Добавляется (новое, отсутствует в прототипе):**
- `profiles` (роли admin/manager), auth, защита маршрутов; гость («Пользователь») — калькулятор без входа;
- `proposals` + `proposal_items` со **snapshot** названия услуги и цены (историческое КП не меняется);
- статусы КП, номера `КП-YYYY-NNN`, скидка, список КП, поиск/фильтр/сортировка, копирование, удаление, просмотр, печать;
- dashboard;
- `price_history` (архитектура);
- backup-экспорт с валидацией по zod и предпросмотром импорта.

## 8. Вывод

Прототип является надёжным функциональным и визуальным референсом. Бизнес-логика расчётов простая и переносится полностью. Основная работа — не в магии расчётов, а в архитектуре: разнести UI / логику / данные по слоям, добавить auth, хранилище и модуль КП с фиксацией цен.

# DECISIONS — зафиксированные решения

Этот файл фиксирует решения, принятые в ходе разработки MVP, для прозрачности в будущем.

## D1. Бэкенд отложен; фронтенд на mock-слое
Пользователь выбрал «сначала фронтенд на моках, бэкенд потом». Все данные — через контракты-провайдеры (`services/module.ts`). Текущая реализация — localStorage. При подключении Supabase меняется только `VITE_DATA_MODE` и добавляются супреабе-провайдеры; UI, хуки и бизнес-логика не меняются.

## D2. Деплой — GitHub Pages
Требование: «готовый проект полностью должен запускаться на github». SPA собирается в статику (`base: './'`), маршрутизация — HashRouter (без server-side rewrites, работает под путём `/protuning/`). Публикация — GitHub Actions `deploy.yml`. Vercel опционален, конфиг приложен.

## D3. Деньги — целые рубли
Цены и суммы хранятся целыми числами (`integer`); сумма — целочисленная, ошибок округления нет. `null` — «цена не задана/услуга не предлагается». Формат — единый `lib/money.ts` (`ru-RU` + ` ₽`, как в прототипе).

## D4. Snapshot цен в КП
При сохранении КП фиксируются `service_name` и `price` в `proposal_items`. Изменение прайс-матрицы не влияет на сохранённые КП (требование ТЗ §9).

## D5. Номер КП — `КП-YYYY-NNN`
Порядковый номер в пределах года (уникальный). Mock: счётчик в localStorage; prod: DB-контракт `nextNumber(year)` с retry на уникальность.

## D6. PDF — печать через `@page A4`
Без pdf-движка; отдельная print-страница `/proposals/:id/print`, `window.print()`, `@page { size: A4; margin: 0 }`. Соответствует референсу, не ломает вёрстку, не требует бибliотек.

## D7. Фото — сжатие и localStorage на mock
Canvas-сжатие до 1200×760, JPEG 0.82 (как в прототипе). Mock хранит dataURL (лимит ~5 МБ); при переполнении — понятная ошибка через toast. В prod — Supabase Storage.

## D8. Auth — email + пароль (mock)
Seed из трёх ролей: `admin@protuning.ru`, `manager@protuning.ru`, `viewer@protuning.ru` (пароль `demo1234`, только для demo). Пароли хэшируются даже в mock (ит.men). В prod заменяется Supabase Auth, интерфейс `AuthProvider` тот же. Демо-режим помечается бейджем в UI.

## D9. Селект услуг — session-only
Выбор услуг калькулятора — локальное состояние страницы, отображается на персистенцию (не в lanternsо obliter). Смена авто сбрасывает выбор (бизнес-правило прототипа).

## D10. Компонентная структура — каждая ответственность отдельно
UI, запросы, бизнес-логика, валидация — разные модули; запрет `any` в продукте; тип `string` для UUID генерируется (`crypto.randomUUID()`).

## D11. Цены в матрице: `null` = пустая
Пустая ячейка матрицы = `null` (не `""`, не `undefined`, не `NaN`). Поле с `null` показывает `—`, при вводе пустого значения сохраняется `null`.

## D12. Учётная запись demo
На экране логина доступны быстрые входы под тремя ролями (для демонстрации на GitHub Pages). Явно отмечено как DEMO.
